# Architecture

**Min3DStry is a 1:1 port of upstream Mindustry (v8 build `160.8`) to New Nintendo 3DS/2DS — not a custom clone or demake.** Target ARM11 homebrew on New Nintendo 3DS/2DS, adapting real pinned upstream Mindustry/Arc source code and content while keeping 3DS services behind platform interfaces. Upstream code may be modified where needed for ARM11/TeaVM compatibility, 3DS memory/performance budgets, and 3DS platform adapters as long as the game stays technically original Mindustry v160.8 (including `.msav` compatibility and cross-platform Java PC multiplayer). The [upstream port plan](upstream-port.md) defines the reference release and 1:1 compatibility requirements.

## Upstream v160.8 ARM11 Bring-Up

- [Upstream source runtime & resource probes](../research/upstream-runtime/README.md): Pinned Mindustry v160.8 + Arc `7445105cd2` compiled with TeaVM C (`-Os` default with dead-string pruning in `arm11/prepare.py`, callsite compaction in `arm11/compact_callsites.py`, and `arm11/build.sh`) against `libctru` adapters and verified across JVM, host C, and Azahar `2126.2` Old/New 3DS modes.
- [Offline single-player Ground Zero](gameplay/offline-singleplayer.md): Standalone ARM11 vertical slice (`singleplayer` / `singleplayer-sim`) combining `UpstreamSinglePlayerSession`, `UpstreamSinglePlayerApp`, `m3ds_input` HID/touch input, `groundZero.msav` loading, copper mining, block construction/deconstruction, wave spawning, and `.msav` Virtual SD save/reload (`44.44` MiB Old 3DS static subtotal; physical hardware and `>= 24 FPS` optimization pending `#43`).
- Live PC `v160.8` multiplayer, touch UI & stock HUD: `network-render` connects over Wi-Fi/sockets to unmodified Java PC `v160.8` servers with full world-atlas rendering, touch catalog/config/mining ([touch-build-palette.md](gameplay/touch-build-palette.md)), combat/waves ([live-combat.md](gameplay/live-combat.md)), and stock font status/objective HUD ([live-hud.md](rendering/live-hud.md)).
- [Combined offline and stock-server build](../research/upstream-runtime/README.md#combined-offline-and-stock-server-build): The experimental `unified` entry point uses the same ARM11 ROM for either mode. An integrated build completed a campaign progression and save scenario and a stock Java server session on each Azahar profile. Its 66.49 MiB offline configured subtotal exceeds the Original 3DS 64 MiB application budget. New 3DS is the physical acceptance target for 100% completion, including sustained 24 FPS within its application-memory budget. Original 3DS remains an emulator compatibility target. Its 64 MiB fit and physical performance are tracked separately and remain open, as does physical cross-play.
- Campaign progression & save verification: ARM11 probes verify sector metadata, slot discovery, tech-tree/research state, planet grid state, and `Saves.load` discovery/launch ([campaign-progression.md](porting/campaign-progression.md), [campaign-verification.md](porting/campaign-verification.md)).
- [Embedded TeaVM save loader](porting/embed-loader.md): `./dev.sh loader` transpiles the pinned `SaveIO` producer and packs `build/teavm-loader/libm3dsloader.a`; `./dev.sh build` generates it when missing (or when `M3DS_REBUILD_LOADER=1`) and passes `TEAVM_LOADER_DIR` to make. Tooling inputs are `UPSTREAM_MINDUSTRY` (absolute pinned checkout), `MINDUSTRY_SERVER_JAR` (defaults to `<parent>/server-release.jar`), `ARC_CHECKOUT` (defaults to `<parent>/Arc`) and `GRADLE_BIN` (defaults to the checkout `gradlew`, then `gradle`). Generation requires a devkitARM environment (`DEVKITARM`/`DEVKITPRO`, sourced from `/opt/devkitpro/3dsvars.sh` when available); the Docker build only links an archive that a native devkitARM environment already produced. CI asserts the strong loader symbol wins over the weak stub in `build/min3dstry.elf`.

## 3DS Platform & Hardware Test Harnesses (NOT the Game)

> **Note for agents:** The native C prototypes below validate 3DS GPU rendering, audio, hardware detection, host testing, and tooling. **Do NOT expand them into a bespoke simplified Mindustry clone**; full gameplay, content, and simulation come from upstream Mindustry v160.8.

- [Citro2D bounded rendering prototype](rendering/citro2d-prototype.md) (`M3dsRenderBackend` + `M3dsBoundedScene` with clamped zoom, bounded effects, and a lighting fallback; host-tested, 3DS-built via `./dev.sh build`, and emulator-tested in Azahar `2126.2` via `./dev.sh emu-test`; physical hardware verification pending).
- [Top-screen minimap prototype](rendering/minimap.md) (`m3ds_minimap_render`, host-tested and visible in Azahar screenshots; upstream HUD/menu parity pending).
- [Pause-menu HUD prototype](ui/pause-menu.md) (`M3dsPauseMenu` Resume/Reset Camera/Quit state machine, top-screen dim/panel pause overlay, bottom-screen text HUD and Select/D-pad/A integration; host-tested and emulator-tested on both models, upstream menu art pending).
- [Bottom-screen touch controls](ui/touch-controls.md) (`M3dsTouchAction` hit regions and tappable pause rows map touch to the existing pan/zoom/menu paths; host-tested and emulator-booted, graphical button art and touch injection pending).
- [Hardware detection profile](hardware/detection.md) (`M3dsHardwareProfile` + `libctru` probe, host-tested, 3DS-built, and emulator-tested across Old/New 3DS modes in Azahar `2126.2`; physical Old/New 3DS hardware verification pending).
- [Memory budget](hardware/memory-budget.md) (`M3dsMemoryBudget` bounded arena derived from the detected application-memory region, host-tested and Azahar-tested; the upstream TeaVM heap budget remains separate).
- [Deterministic worker scheduling](hardware/worker-scheduling.md) (`M3dsWorkerPool` fixed-chunk jobs with serial fallback, host-tested and Azahar-tested for checksum determinism; the simulation tick remains single-threaded and physical timing is pending).
- [Gameplay parity harness](testing/parity-harness.md) (`M3dsParityState` + canonical scenario `starter_copper_defense_v1`, matching the fixture on host `-O0`/`-O2`, Azahar Old/New 3DS ARM11, and a physical New 3DS XL).
- [Hardware deployment & log streaming](hardware/deployment-and-logs.md) (`./dev.sh device` / `tools/device_deploy.py`, including `benchmark-report` checking `[MIN3DSTRY] MEM`, `[MIN3DSTRY] BENCH`, and `UPSTREAM_MEMORY` against `O3DS` 64 MiB / `N3DS` 124 MiB budgets; host-tested for SD staging and log tooling, hardware-tested for Wi-Fi deployment and log streaming on a New 3DS XL).
- [Physical verification runbook](hardware/verification-runbook.md) + `./dev.sh device evidence`: turns a captured `[MIN3DSTRY]` log into checked Markdown/JSON evidence (model/app-memory profile, loader/tile/save hashes, simulation parity, worker checksum, frame drops, memory budget, ROM SHA-256); host-tested, pending a physical run for `physical-hardware-parity`.
- [NDSP audio mixer prototype](audio/ndsp-mixer.md) (`M3dsAudioMixer` + `libctru` NDSP backend, host-tested via mock backend, 3DS-built via `./dev.sh build`, and missing-`dspfirm.cdc` fallback verified in Azahar `2126.2`; physical hardware playback with DSP firmware pending). [Upstream audio asset conversion](audio/asset-conversion.md) provides a pinned PCM16/provenance slice and a bounded [audio registry](../include/audio/audio_registry.h), [music-assets.md](audio/music-assets.md) (`tools/stage_music_assets.py`) stages all 16 pinned `.ogg` soundtrack tracks, and [music-streaming.md](audio/music-streaming.md) adds a double-buffered Tremor (`libvorbisidec`) NDSP streamer; the live client routes stock weather loop requests and fades through `SoundControl`. [The live weather replay](audio/ndsp-mixer.md#live-multiplayer-weather) exercises that route in Azahar’s no-DSP mode. [Audio events](../include/audio/audio_events.h) map nine logical audio IDs to mixer playback in the platform test harness.
- [Upstream v160.8 network framing & handshake](net/upstream-protocol.md) (`mindustry_net` Issue #31 wire-exact framing/handshake shim & test oracle paired with the reusable `libctru` `socInit` socket adapter `net_3ds.c`, host unit-tested, live-verified against unmodified `server-release.jar` v160.8, and 3DS-built via `./dev.sh build`; full `#44` TeaVM `NetClient` wiring and on-console Wi-Fi session pending).

Track toolchain builds, emulator boot, physical hardware boot, gameplay parity and upstream multiplayer independently. Record hardware model, build SHA and test scenario alongside measurements. Audit upstream and dependency licenses before importing code or assets.

## Portability research

The Java-to-native evaluation (issue #1) compares JVM hosting, ahead-of-time Java, transpilers and native reimplementation against the documented 3DS limits, and includes a reproducible host/ARM11 proof of concept. See [Java-to-native feasibility](research/java-to-native.md) for the recommendation, memory and cycle budgets, determinism/networking analysis and license audit. Its evidence is host-tested and cross-compiled only; it makes no emulator or hardware claim.
